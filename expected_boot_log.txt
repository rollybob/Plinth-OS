# Smoke test contract, both directions. See xtask check_smoke_output.
#
#   1. Every non-blank, non-comment line below must appear in the captured
#      serial output, in order. Matching is substring-based, so an expectation
#      may be a stable PREFIX of a line whose tail varies.
#   2. Nothing else may appear. Any captured line that satisfies no expectation
#      and matches no `#!allow` pattern fails the run.
#
# Direction 2 was added 2026-07-30 (K-003). Before it, this gate was a plain
# subsequence match: unmatched output was skipped silently, so new kernel output
# was unverified until someone remembered to add it here. It did not notice a
# whole new demo printing eight new lines. At the moment it was turned on it
# found 179 captured lines that nothing checked -- roughly half the boot.
#
# `#!allow <substring>` lines declare output that is real but cannot be
# asserted. They are ordinary comments to the expectation parser, so they live
# in this file rather than in xtask. The allowlist is at the BOTTOM, and it is
# the honest statement of what this gate does not cover -- keep it short, and
# prefer asserting a stable prefix over allowing a whole line.

# Framebuffer RECLAMATION (Design/cap_reclaim.md D6) -- the case where the process
# that loses the capability is not the one that gets it back. fbreclaim-user is
# granted the whole screen, draws and hashes a frame, TRANSFERS the capability to a
# child, and the child FAULTS while holding it. By fault, not a clean exit: a clean
# exit can be asked to hand the screen back (shellapp does exactly that), and the
# failure this exists for is the one nobody can be asked to handle. Before
# reclamation the child's death destroyed the only Framebuffer capability in
# existence -- no syscall mints one -- so nothing could draw for the rest of the
# boot, and clicking gfxbound in a shell-launched-apps world would have bricked the
# display.
#
# Four lines carry the proof, in order. The child's "holding the screen" line comes
# after a real draw through its mapping, so it demonstrably had the screen rather
# than merely a slot. "screen came back" means the death-wake arrived with a real
# capability slot instead of the NO_CAP a v2.8 kernel always returned (ABI v2.9) --
# without that the parent could not have found it, since nothing enumerates a
# capability table. And the two hashes DIFFER: the parent paints a different colour
# the second time, so a stale mapping could not masquerade as the reclaimed one.
#
# On a pre-reclamation kernel the second hash is unreachable, not merely different,
# which is what makes this a regression test. Frames are bracketed by xtask for the
# same D7 reason as gfxrevoke: reclamation must never route a framebuffer through
# the Frame arm and hand ~1000 MMIO pages to the allocator.
plinth: fbreclaim demo: 1 processes
fbreclaim: lent hash 0xf10a511b535ec044
fbreclaimchild: holding the screen, now faulting
plinth: [user fault] #PF
plinth: terminating user process
fbreclaim: child died, screen came back
fbreclaim: reclaimed hash 0xd12799246c3d6e04
plinth: fbreclaim demo: all done

# The SAME reclamation, driven through the `spawn_and_wait_cap` helper instead of
# by hand (ABI v2.9, K-012). The helper shipped 2026-08-05 with nothing exercising
# it: fbreclaim above proves the kernel path, but it calls sys_spawn and
# sys_recv_cap itself, so the library wrapper that packages them had no watch.
# Both demos are kept on purpose -- fbreclaim stays on the raw syscalls so a
# failure stays attributable. If both went through the helper, a kernel regression
# and a library regression would produce identical output.
#
# It reuses fbreclaimchild (SPAWNABLE id 5) rather than adding a near-copy, which
# is why that child's line appears here a second time.
#
# It lends a Framebuffer because that is the only thing it CAN lend. The 08-05
# handoff proposed lending a Ring or an ordinary Frame; `release_action` scopes
# reclamation to Framebuffer (cap_reclaim.md D2, narrowed at ruling time), so a
# lent Frame is freed with the dying child and the wake carries NO_CAP. Measured,
# not assumed -- the Frame version was built first and reported no landing slot,
# with a flat frame bracket because the frame went to the allocator rather than to
# the lender. Rings are built from Frame capabilities, so they are out too.
#
# The two hashes carry the same proof they carry above, and differ for the same
# reason. What this adds is a watched failure for the HELPER: swap its call for
# the two-value `spawn_and_wait` and the demo takes its "no landing slot" exit and
# turns this file red. That collapse is K-012 itself, so the regression this
# guards against is the one that was just fixed.
#
# The endpoint bracket xtask puts around this demo does NOT prove the helper
# released its spawn handle, though it reads that way. Deleting that release
# leaves the bracket completely green: it samples before and after the whole
# demo, and by then the process has exited and teardown has released its entire
# table. It is kept for what it does prove -- the spawn endpoint does not outlive
# the demo. A leaked handle needs caprelease-user's shape to catch: a loop run
# past what the system can have in flight. That loop is the last line below.
#
# The loop transfers NOTHING and spawns quietworker rather than fbreclaimchild.
# A handle is minted by every spawn whether or not a capability rides along, so
# the framebuffer is irrelevant to this claim -- and dropping it is what keeps
# twenty rounds of a chatty, faulting child (sixty lines: its own, the fault, the
# termination) out of this file to say something none of them are about. It runs
# in the same process, still holding the reclaimed framebuffer, so the budget it
# contends for is the honest one. Watched failing: delete the helper's
# `sys_cap_release` and the loop dies with "spawn failed at round 7".
#
# What runs out at round 7 is the EIGHT-endpoint pool, not the 16-slot capability
# table -- there were still about six slots free. Every spawn creates an endpoint
# for its result channel and the handle is what keeps it referenced, so leaking
# the handle pins the endpoint. Seven rather than eight because the framebuffer

# Framebuffer VOLUNTARY RELEASE (cap_release-on-reserved, ruled 2026-08-15) -- the
# polite counterpart to fbreclaim above. fbreclaim proves a lent screen survives the
# borrower's DEATH; this proves it comes home when the borrower politely RELEASES it
# with cap_release. fbrelease-user draws and hashes a frame, TRANSFERS the screen to
# a child that releases it (not a fault, not an IPC transfer-back), and then re-maps
# the very slot it lent from -- which the reservation held open -- and hashes a second
# frame. The child's "released the screen" line comes after a real draw through its
# mapping, so it demonstrably had the screen. The two hashes match fbreclaim's byte
# for byte (identical paint), and DIFFER from each other, so a stale mapping cannot
# masquerade as the returned one.
#
# On the pre-ruling kernel the second hash is unreachable, not merely different: a
# voluntary release unmapped and DROPPED the borrowed capability, so the lender's
# reserved slot was stranded empty and the re-map failed -- a crashing borrower
# returned the screen while a well-behaved one did not. That is the regression this
# guards, the same "green but leaking reserved slot" class the slice-2 fix closed,
# reached through the release verb. Frames and endpoints are bracketed (no leak):
# reclamation must never route a framebuffer through the Frame arm (D7).

# splash, a home screen of app icons, arrow-key navigation and a MOUSE POINTER,

# EventSource (slot 2) and the mouse EventSource (slot 3). Scripted scancode AND

#

# The pointer moves one column left onto CRASH and clicks. CRASH is a real app

# framebuffer capability. Nothing is handed back -- there is nobody left to hand it.
#
# The kernel reclaims the capability during teardown and reports the slot it landed
# in on the death wake itself (ABI v2.9), so the shell's IPC_PEER_DIED branch remaps

# the "back home hash" that follows is byte-identical to every other one in this

# exited politely, and cannot tell the difference by the time it has redrawn.
#

# framebuffer, so a shell that launched a crashing app lost the display for the
# rest of the boot -- which is precisely why clickable apps could not ship first.
